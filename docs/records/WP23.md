## Important permanent grant checkpoint

- An adjudicated occurrence authorizes bounded, typed permanent currency or discovery envelopes. Issue commits the occurrence claim, outbox rows and replayable authority frontier in one SQLite transaction. Replayed recipient order is stable. A changed amount at the same key conflicts and a stale frontier rolls back the entire issue.
- The signed, versioned message uses the established native public-key fingerprint and a grant-specific signing domain. The expected run binding scopes issuer, recipient profile, recipient key, rules and catalog. A second signing domain authenticates the recipient's acknowledgement of the exact application digest.
- A personal application applies exact amounts or records a unique profile-wide discovery. Replay returns its original durable receipt and a matching acknowledgement. Lost write results are resolved by exact operation ID and digest before a positive acknowledgement. Acknowledged outbox rows release the envelope and retain their receipt and identity. Out-of-order grants remain individually pending.
- The process fixture uses a file courier in a disposable directory to observe commit, process death, cold reopen and retry without a live link. Remaining work includes the live authenticated transfer and role reversal, persisted run/key binding, run-scoped and solo atomic awards, and repeated authorizations for an already recorded discovery. A conflicting discovery currently refuses a second application and withholds acknowledgement. Ordinary currency batching, the oldest-earning deadline, mandatory flushes and fault suspension comprise the second scheduled increment. WP24, WP26 and later consumers await full-package review.
