## 5. Known Limitations and Open Follow-Ups

1. **Antigravity in-app MCP server reload (resolved):** `%USERPROFILE%\.gemini\config\mcp_config.json` was updated to `GODOT_MCP_PROJECT_PATH=D:\Mamduh\Personal\a-game-i-actaully-play`. After Antigravity restarted, its native `godot` MCP server connected directly to the live production Godot 4.7-stable editor and passed all independent verification checks (see §6).
2. **Official export template `disable_path_overrides`:** Official Godot 4.7-stable export templates block arbitrary `res://...` scene path arguments on the exported executable CLI (`disable_path_overrides=yes`). `Windows Dev` retains `dev/fixtures/harness_probe.tscn` inside its `.pck` (`has_dev_fixtures=true`) while `Windows Player` excludes it (`has_dev_fixtures=false`). Editor/MCP runs launch fixtures directly via `game_start(scene_path: "res://dev/fixtures/...")`; if a later package (e.g., WP14/WP32) needs exported Dev builds to enter a fixture directly, it should route through a dev-feature-gated `--` user argument rather than raw scene path overrides.
3. **Editor plugin strings in `project.binary`:** Godot writes `[editor_plugins] enabled=...` metadata into exported `project.binary` by default. Export templates do not include `EditorPlugin`, none of the plugin files exist in either `.pck`, `global_script_class_cache.cfg` contains only `AppPaths` and `BuildInfo`, and `autoload/MCPRuntimeServer` is stripped completely from `project.binary` by `0MCPExportStrip`.
4. **Independent review complete:** Antigravity has independently reviewed and approved `32bab3c23133b14e3ec4fa7b134373097b4f12ab` on `dev` (§6). Downstream packages `WP02`, `WP03`, `WP04`, `WP05`, `WP14`, and `WP15` are eligible to start under Bounded Autonomous Development while preserving all package-specific qualification gates.
