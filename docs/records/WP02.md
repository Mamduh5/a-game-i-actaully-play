## Admission and replay contract

The authority captures preparation identity, rules, catalog, challenge, seed and the locked seat-to-realm roster. A trusted adapter supplies its bound seat separately from the claimed seat. The current admission window is the next open tick. Sequence floors apply per seat across ticks. The authority closes the batch in lexical seat ID and ascending sequence order, cancels conflicting valid envelopes at a shared sequence, and cancels only the over-budget seat's batch when the 64-intent technical limit is exceeded. `QUEUED` means staged. The closed result reports final admission. These choices define the local interface for WP06–WP08. Downstream gameplay priority and causal arbitration remain governed by GDS §3, including PR12.

Rule execution is synchronous inside the authority. Presentation reads detached copies, and the dev trace samples those copies after closure. Named RNG streams use hash-derived seeds and Godot RNG state with draw counts. The checkpoint schema pins the engine build and setup identity and captures closed tick, sequence floors and stream state. A fresh authority can restore the same locally supplied frontier. WP06/WP12 own authenticated admission, delivery and filtered guest data. WP07/WP25 own travel and realm updates. WP09 owns consequential resolution and safe numerical faults. WP13/WP24 own durable checkpoints, recovery proof and epoch transitions.

### Findings and downstream notes

No blocking or material defects found. Two non-blocking observations for downstream packages:

1. **Future `RunIntent` payload equality (`src/run/run_authority.gd:60`):** Currently `DUPLICATE` vs `CONFLICT` compares `previous.action == intent.action`, which is complete for WP02's envelope fields. When WP08 extends `RunIntent` with aim, target or movement payload fields, update this check to full-payload equality so differing payloads on the same sequence classify as `CONFLICT`.
2. **Untyped dictionary key equivalence in `restore()` (`src/run/run_authority.gd:141`):** Godot 4 untyped `Dictionary.get()` accepts `String` keys for `StringName` lookups in `saved["sequences"]`; `_install()` safely normalizes `_last_sequences` keys back to `StringName` from `_realms`. WP24 should still enforce strict schema/type validation at the disk/network recovery decoder boundary.
