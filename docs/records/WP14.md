## Observation and input boundary

The labeled disposable course runs at the normal 60 Hz physics rate. A deterministic Python standard-library policy runs in its own process and receives one bounded frame over redirected stdin. Fields are player and beacon positions, the drawn hazard rectangle after the warning appears, the manual prompt, the visible button center, and completion. The policy has no game-state object, fixture evidence path, debugger endpoint, game seed or concealed recipe in that interface. The evidence collector writes hidden values only to disk for post-run comparison. OS account permissions are shared, so this is a scoped tool boundary for the reviewed policy code.

The actuator validates the policy reply and produces ordinary physical keys from the current InputMap and paired viewport pointer events. Cue interaction still requires position, a valid manual press and a real focused Control gesture. The fixture and tooling are dev-only. The supervised CLI runner launched and stopped the isolated runtime with MCP opted out because the shared editor was in use for WP02–WP05 review. WP32 will repeat on actual movement/combat through the normal targeted MCP and pilot workflow. [Godot viewport event propagation](https://docs.godotengine.org/en/4.7/classes/class_viewport.html#class-viewport-method-push-input)
