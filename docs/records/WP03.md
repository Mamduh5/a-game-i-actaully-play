## Catalog contract

An authored `CatalogBundle` lists typed `CatalogEntry` resources under a catalog revision. A link identifies one stable ID and target revision. Compiling detaches the read-only definitions, including nested link values, rank order and capability lists. Lookup and resolution require a valid snapshot. Ownership prerequisites and ordinary content references have separate cycle rules. Runtime counters live in independently allocated owner instances.

The recipe check reserves the named base slots and required equipped runes, resolves an attainable order of exact Evolution selections, then checks simultaneous Fusion occupancy and retained external catalysts. Both base acquisition and rank advancement are assumed available once the catalog's hard prerequisites pass. Form-only capabilities require an earlier provider form. A provider that loses its capability changes the legal order. Fusions use exact forms and retain two occupied slots. Preserved capabilities belong to the specific contributing slot.

This is a schema and static reachability check using the V42.6/R1 ten-slot and two-rune limits. Named mechanics, actual rank/reward payment, unlock execution, Fusion timing, content completeness and ordinary-play acquisition witnesses belong to WP19–WP21, the content packages and WP38. The F06 text resource is a development fixture.
