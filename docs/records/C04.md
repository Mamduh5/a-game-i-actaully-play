- **Blocking findings on Acrobat Vault (`f21ae3e`):**
  1. **`C04-O1` (Medium — `src/controls/vault_travel.gd` L53–65): Crossing a `VAULTABLE_BLOCKER` skips steps, teleports in one tick, and collapses the 14-step airborne travel window.**
     - **Root cause:** `VaultTravel.advance()` scans `for index in range(_sample + 1, _steps + 1)` until `_clear_to_land(draft, _actor)` passes and immediately sets `_sample = index` and adopts `draft`, consuming all skipped obstacle steps in a single tick.
     - **Live reproduction (`dev-review-35b156f/adversarial-probe.json`, `c04_vault_timing`):** Identical 64-unit / 14-step Vaults committed on tick `2` from `x = 62.0` toward `x = 210.0` with a `ground_only = true` strike landing inside the 14-step window:
       - `flat` (no obstacle): `airborne_ticks = 14`, lands tick `16`, `max_single_tick_dx = 4.57`, **`final_hp = 100`**.
       - `low_r4` (the `4.0`-radius low solid from `test_acrobat_vault.gd`): `_sample` jumps `3 -> 11` on tick `6` (`max_single_tick_dx = 36.57`, 8x teleport), collapsing `airborne_ticks` from `14` to **`7`** (lands tick `9` instead of `16`).
       - `low_r12` (`12.0`-radius low solid): `_sample` jumps `1 -> 13` on tick `4` (`max_single_tick_dx = 54.86`, 12x teleport), collapsing `airborne_ticks` to **`3`** (lands tick `5`), so the tick-15 ground-only strike **hits the prematurely grounded Acrobat (`final_hp = 84`)** while the flat-ground Vault stays airborne and avoids it (`100 HP`).
     - **Required fix:** Preserve the 14-step travel/airborne duration and smooth step cadence when crossing a `VAULTABLE_BLOCKER` (without leaving an invalid overlapping settled pose on interruption or landing), and add a unit regression asserting both airborne-window duration and ground-only avoidance across low obstacles.
  2. **`C04-O2` (Medium — `src/world/world_exploration.gd` L320 & L356): `WorldExploration.checkpoint()` / `restore()` drops the `vaultable` flag on route solids.**
     - **Root cause:** `place_route_solid(..., vaultable: bool = false)` creates a `VAULTABLE_BLOCKER` (`4096`), but `checkpoint()` does not serialize `vaultable` and `restore()` calls `place_route_solid(id, center, radius, durability)` with default `vaultable = false`.
     - **Live reproduction (`dev-review-35b156f/adversarial-probe.json`, `c04_vault_checkpoint`):** A `vaultable = true` solid has category `4096` before checkpoint (Vault crosses to `x = 126.0`), but after `WorldExploration.restore(floor.checkpoint(), [SEAT])` its category silently degrades to `1` (`SEALED_BLOCKER`) and the exact same Vault clips at `x = 76.0`.
     - **Required fix:** Persist and validate the `vaultable` flag in `WorldExploration.checkpoint()` / `restore()` (preserving backward compatibility for checkpoints without the optional field) and add a round-trip unit test verifying low vs sealed solids survive checkpoint restore.
