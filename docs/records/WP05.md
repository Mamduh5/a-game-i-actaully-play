1. **Approved native backend & mode:** Adopt `godot-sqlite v4.9` (SQLite `3.51.0`) with **`locking_mode=EXCLUSIVE`** (acquired via an opening write before admitting writable play), **`journal_mode=DELETE`**, and **`synchronous=EXTRA`** (readback `3`). `WAL` remains unselected on SQLite `3.51.0` due to the documented WAL-reset defect scope; `DELETE/EXTRA` satisfies measured latency bounds cleanly on local NTFS.

Clean-checkout tooling in WP13/WP41 MUST execute the two-step headless GUI-editor bootstrap (`Godot_v4.7-stable_win64.exe --headless --path <P> --editor --quit-after 180`, then `--import`). **Windows shell nuance verified empirically:** because `Godot_v4.7-stable_win64.exe` is a Windows GUI-subsystem binary, bare PowerShell `&` returns asynchronously before initialization finishes; automation MUST wait synchronously (`Start-Process -Wait -PassThru` in PowerShell or `subprocess.run` in Python) and verify `--log-file` error absence.
3. **Boundaries preserved for downstream packages:** The production repository remains free of `godot-sqlite` until WP13 integrates it. WP13/WP23 still owe game-schema migrations, full-disk/read-only/I/O fault handling, the 5-second oldest-ordinary-earning commit deadline, ambiguous-commit reconciliation, and MIT license notice distribution (`godot-sqlite` + `godot-cpp`).
