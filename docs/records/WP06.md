## Signed admission state

Checkpoint `510b1d0219f7f9bb0fe92ee847050eeaacdbe7d2` adds a fixed-size challenge for the original host, run, generation, attempt, purpose, paired guest key and fresh nonce. The in-memory seat owner issues scoped invitation tokens, compares credential digests in constant time, expires bounded pending attempts and publishes control only after signature verification. Reclaim rotates the credential and invalidates competing attempts. A lost acceptance can retry with the preceding credential and a fresh signature until the new controller acknowledges. Unit tests cover a wrong or expired invitation, a replayed signature, an uninitialized seat, generation rejection, competing claims and fencing. Native GUT ran 76/76 tests and 795 assertions. `.qa-evidence/WP06/admission-gut.xml` SHA-256 `df333c3529e1bca6b8ee391cabc4a68e3277609441d64a344879299d67ea1342`.

## Release reclaim after abrupt guest loss

The separate Windows release fixture terminates only the admitted disposable guest after two application echoes, waits for host detection and launches a new guest with the previous rotated credential and fresh signed proof. The host remains live throughout. The original single reclaim run detected loss in 5279 ms. A repeat left the first new ACCEPT unacknowledged, then used the preceding credential on a competing connection. The host fenced the pending connection before commands could reach it. The winning guest exchanged both application frames, received a new credential and left via the authenticated host drain. Loss detection in the final repeat took 5281 ms. The wrong private invitation and premature command each produced one rejection, zero admissions and zero commands.
