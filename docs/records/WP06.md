### Independent diagnostic dispositions

1. **`ERROR: Parameter "p_mutex->mutex" is null.` at `godot_mbedtls_mutex_free (modules/mbedtls/register_types.cpp:54)` — SCOPED ACCEPTANCE ON PINNED GODOT `4.7-stable`.**
   - Reproduces deterministically (exactly 3 reports per server `ENetConnection.destroy()`), exclusively on the host during `disconnected` / `draining` / `host-draining` teardown, never on guests and never during active handshake or frame exchange.
   - Root cause is an upstream Godot `4.7-stable` mbedTLS `DTLSServer` destruction defect (Godot Issue #125216). Across 10 consecutive bind/connect/drain/destroy cycles per interface, private memory stabilized with **`late_growth_bytes = 0`** (`36,618,240` bytes loopback; `36,696,064` bytes private IPv4).
   - **Narrow scope (not a blanket waiver):** Accepted only at exact site `modules/mbedtls/register_types.cpp:54`, strictly after host drain/disconnect teardown, with bounded memory verified. Any occurrence during handshake/active play, any guest-side diagnostic, any other ENet/mbedTLS error or unbounded resource growth remains a hard failure. Re-evaluate on any engine pin update.
2. **`ERROR: TLS handshake error: -30464` at `_do_handshake (modules/mbedtls/packet_peer_mbed_dtls.cpp:100)` on direct guest-side ENet close — UNRESOLVED ENGINE QUIRK / NOT WAIVED (MITIGATED BY MANDATORY PROTOCOL CONTRACT).**
   - `-30464` (`-0x7700` = `MBEDTLS_ERR_SSL_UNEXPECTED_MESSAGE`) occurs during active host listening (`boundary-observed`) when a guest initiates direct ENet/DTLS close while the host remains open (the guest's trailing DTLS `close_notify`/record reaches `DTLSServer` after peer removal and is rejected as a non-ClientHello handshake record).
   - Does **not** occur on host-owned voluntary departure (`LEAVE` → host fences seat and initiates peer close) or on abrupt guest process loss (`abrupt-reclaim`).
   - **Binding contract for WP12/WP24/production:** The `--client-close` control remains an explicitly failing, unwaived engine-teardown control. Voluntary client departures **MUST** use authenticated host-owned `LEAVE` rather than direct client-side ENet teardown against a live host. Unplanned drops follow the verified abrupt-loss path.

### Non-blocking findings and retained limits

- **`WP06-F1` (Low / non-blocking hardening for WP12):** `src/transport/native_dtls_link.gd:158` checks IPv6 ULA via `lower == "::1" or lower.begins_with("fc") or lower.begins_with("fd")` without checking that the first IPv6 hextet is 4 hex digits (`lower.find(":") == 4`). Short first-hextet addresses such as `fc::1` (`00fc::1`) and `fd1::1` (`0fd1::1`) return `true` despite falling in IANA-reserved space rather than RFC 4193 `fc00::/7` (`adversarial-probe.log`). Non-blocking because no public/Internet-routable IPv4 or IPv6 (`2000::/3`), unspecified (`0.0.0.0`, `::`), link-local (`fe80::`) or multicast address is admitted, and `create_host_bound()` only binds locally assigned addresses. **Action:** tighten to `lower.find(":") == 4 and (lower.begins_with("fc") or lower.begins_with("fd"))` on the next transport touch (WP12).
- **`WP06-O1` (Low / protocol boundary):** `src/transport/native_admission.gd:110-118` consumes `_offers[seat]` on `INITIAL` `complete()` without recording `retry_hash`, so a lost `ACCEPT` on initial join cannot be retried with the consumed invite or re-offered in the same generation (`adversarial-probe.log`). Matches TDS §5 (which specifies lost-acceptance retry for `RECLAIM`); WP12/WP24 should account for initial-join `ACCEPT` loss explicitly on lossy links.
- **`WP06-O2` (Low / protocol boundary):** `src/transport/native_session_host.gd:85-87` filters `batch.commands` against `_driver.can_send()` at the end of `pump()`, discarding any application command that arrives in the same `pump()` batch immediately before `LEAVE`. WP12 clients should flush/acknowledge final commands before sending `LEAVE`.
- **`WP06-O3` (Observation):** Passing raw bytes containing embedded NULs into `NativeHostPin.enroll()` logs a non-fatal Godot `Unicode parsing error` on stderr from `get_string_from_ascii()` before failing closed (`adversarial-probe.log`).
- **Retained scope limits carried downstream:** Private-interface evidence ran on one physical host (`172.19.208.1`); multi-host LAN/direct-IP topology, sustained traffic/engine buffering under load, replication/filtering privacy and cross-generation original-host recovery remain owned by WP12, WP24, WP37 and WP40.
