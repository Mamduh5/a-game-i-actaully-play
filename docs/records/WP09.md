### Required correction (blocking WP09 approval)

1. **`WP09-D1` (High · Blocking — `src/combat/combat_kernel.gd:543-549, 586-592`):** **Zero-progress cycle detection falsely aborts legitimate finite alternating chains (`A (paid) <-> B (free)`) as `&"causal_cycle"` at wave 3.**
   - **Governing rule:** [TDS §2 Causal groups](../TDS.md#tds-combat) (*"Interrupt a zero-progress cycle... Do not silently discard a legitimate finite chain"*), [M2 exit / WP09](../IMPLEMENTATION_PLAN.md#wp09) (*"finite vs zero-progress cycles"* · *"A missing target, order-dependent death, hidden state on a guest or discarded legitimate chain holds combat replication"*), and [AGENTS.md](../../AGENTS.md) (*"Preserve legitimate powerful combinations"*).
   - **Root cause:** `_choose_descendant()` builds the ancestry equivalence key using only the current reacting actor's single `rule.resource` (`budget`) plus `_life_image(claim.actor)` and `_life_image(claim.target)`. `_life_image()` encodes `[id, life, hp, barriers, statuses]` and omits actor `resources` (as well as other participating actors' progress across a multi-actor chain like `A (paid) -> B (free) -> C (free) -> A` and any geometry position changes). When `A` spends a finite resource (`charge: 5 → 4 → ... → 0`) and `B` responds with a free reaction (`cost = null`, `budget = ""`) while HP/barriers/statuses cycle via equal damage + `restore_source`, `B`'s wave-3 key omits `A`'s decremented `charge` and matches `B`'s wave-1 key verbatim.
   - **Expected:** A finite alternating chain where `A` has `resources[&"charge"] = 5`, `a_counter` (`HOSTILE_HP`, dmg 1, `restore_source = 1`, cost 1 `charge`) and `B` has `b_mirror` (`HOSTILE_HP`, dmg 1, `restore_source = 1`, free) drains all 5 charges cleanly (`Result.CLOSED`, 12 waves, `A.charge = 0`, `A.hp = 9`, `B.hp = 10`). Likewise for a 3-actor finite ring `A (paid) -> B (free) -> C (free) -> A`.
   - **Actual (`.qa-evidence/WP09-review/adversarial-probe.log` lines 74–78):** `alt_paid_free_finite_chain_result=INTERRUPTED`, `alt_paid_free_finite_chain_fault=causal_cycle`, `alt_paid_free_finite_chain_fault_wave=3`, `alt_paid_free_finite_chain_remaining_charge=5`.
   - **Required fix:** Include all participating/touched actors' canonical state — specifically their sorted `resources` (encoded via `QuantityCodec`) alongside HP, barriers, statuses and draft geometry poses where attached — in the cycle-equivalence snapshot so any genuine finite state change along the ancestry prevents false `&"causal_cycle"` aborts, while true 2-actor and 3-actor zero-progress cycles still interrupt cleanly. Add unit regressions for `A (paid) <-> B (free)` and `A (paid) -> B (free) -> C (free) -> A` finite drainage alongside 2-actor and 3-actor zero-progress cycles.

### Non-blocking hardening finding (recommended in the same revision)

- **`WP09-F2` (Medium — `src/combat/combat_kernel.gd:418-428`):** `_queue_descendants()` gates both attacker and defender follow-ups on `if source == null or source.life != posting.hit.source_life or source.realm != target.realm: continue`. While WP09's current API does not yet expose respawn (`life + 1`) or realm transfer (`realm` change), WP10/WP11/WP25 will allow an attacker to respawn or cross realms while a committed delivery remains in flight. In that case, skipping line 426 would silently suppress the **defender's** own `HOSTILE_HP`, `HOSTILE_LAYER` or `OWN_DEATH` reactions targeting a `fresh_target` in the defender's realm. Gate only the attacker's `_gather_claims(..., source, ...)` (and defender reactions whose `fresh_target.is_empty()`, targeting `counterpart = source`) on `source` life/realm matching.
